# Family Travel Planner — SDD Specification

**Status:** Draft  
**Version:** 1.0  
**Scope:** MVP implementation of the existing CLI agent

## 1. Purpose

Build a command-line family travel planner that accepts a destination, family composition, and budget preference, then returns a structured travel plan generated by Genkit. The plan must use the available flight, hotel, and activity search tools and must be observable in Progress AI Observability.

The product provides recommendations only. It does not search live inventory, make reservations, process payments, or guarantee prices.

## 2. Users and primary scenario

The user is a family traveler planning an exploratory trip. In the primary scenario, a family that normally visits Menorca requests a relaxed, family-oriented trip to Ibiza, with quiet areas, child-appropriate activities, and euro-denominated estimates.

Example invocation:

```text
npx tsx bootstrap.ts Ibiza 2 2 moderate 7 5
```

Arguments are positional:

| Position | Meaning | Default |
| --- | --- | --- |
| 1 | Destination | `Ibiza` |
| 2 | Number of adults | `2` |
| 3 | Number of children | `2` |
| 4 | Budget preference | `moderate` |
| 5 onward | Child ages | Derived ages when omitted |

## 3. Functional requirements

### FR-1: Parse and validate a travel request

The system SHALL construct a travel request with `destination`, `numAdults`, `numKids`, `kidAges`, and `budget`.

The system SHALL reject:

- an empty destination;
- fewer than one adult;
- a negative number of children;
- a non-empty age list whose length differs from `numKids`;
- a child age outside `0..18`;
- a budget other than `budget`, `moderate`, `comfortable`, or `luxury` (case-insensitive).

When child ages are omitted, the system MAY use deterministic defaults for the demo. The generated plan must still be appropriate for the youngest child represented by the request.

### FR-2: Search recommendation data

For each valid request, the agent SHALL have access to these tools:

1. `find-flights(destination, numPassengers)` returning flight options.
2. `find-hotels(destination, checkIn, checkOut)` returning family-friendly hotel options.
3. `find-activities(destination, numAdults, numKids)` returning age-filtered activities.

The MVP MAY use deterministic mock data. Destination normalization SHALL recognize Ibiza and Menorca case-insensitively and SHALL use a safe default dataset for other destinations.

Hotel search SHALL derive a stay length from valid check-in and check-out dates, with a fallback of three nights. The current CLI does not collect dates, so the agent may let the model choose a duration and use the fallback search window.

### FR-3: Generate the travel plan

The agent SHALL generate a plan with this schema:

```text
destination: string
duration: string
summary: string
flights: array of { airline, departure, arrival, price, stops }
hotel: { name, rating, pricePerNight, amenities }
activities: array of { name, category, costPerPerson, duration, description }
totalEstimatedCost: string
```

The model prompt SHALL require:

- a relaxed, family-oriented destination profile;
- activities suitable for the youngest child;
- beaches with shallow, calm water where relevant;
- at least one cultural experience;
- at least one water activity;
- realistic estimates in euros;
- output matching the structured schema.

The system SHALL fail the agent run when no structured model output is returned.

### FR-4: Present the result

The CLI SHALL print the destination, duration, summary, flight options, recommended hotel, activities, and total estimated cost in a readable format. It SHALL print a link to the Progress Observability dashboard after a completed run.

Errors SHALL be reported to stderr with enough context to identify that travel-plan generation failed. The process SHALL always attempt to shut down observability instrumentation.

## 4. Data contracts

All tool inputs and outputs SHALL be validated with Zod schemas before they are passed to or returned from the agent. Prices remain display strings in the MVP (for example, `€85`); numeric money modeling is deferred.

An activity's `minAge` is an internal recommendation field and may be omitted from the final plan. A hotel’s `familyFriendly` flag is an internal filtering field and may be omitted from the final plan.

## 5. Observability requirements

At startup, the application SHALL:

- load environment variables;
- require `GOOGLE_API_KEY`;
- require `OBSERVABILITY_API_KEY`;
- initialize Progress Observability with app name, Google Generative AI instrumentation, and content tracing enabled.

Each agent run SHALL be represented by the native Genkit trace and its generated flow, tool, and model spans. Model usage SHALL be captured by `@progress/observability@3.1.0`, including provider, request/response model name, and available input, output, total, reasoning, and cached-token attributes. The application SHALL NOT add a duplicate manual agent span.

The configured model SHALL default to `gemini-2.5-flash-lite` when `GEMINI_MODEL` is absent and SHALL normalize a provider-qualified value to the `googleai/<model>` form.

The application SHALL call `Observability.shutdown()` during process completion, including the error path.

## 6. Non-functional requirements

- Runtime: Node.js 18 or newer.
- Language: TypeScript with strict compiler settings.
- Execution: CLI via `tsx`; no web server is required for the MVP.
- Determinism: mock tools must return stable results for the same normalized destination and inputs.
- Safety: the agent must not claim that a recommendation is booked, live-priced, or guaranteed.
- Maintainability: domain terms in this document and [`CONTEXT.md`](../CONTEXT.md) are canonical.

## 7. Acceptance criteria

- A valid Ibiza request produces a schema-valid plan containing flights, one hotel, activities, and an estimated total.
- A request with invalid adult count, child count, age count, age range, or budget fails validation with a clear error.
- Ibiza, Menorca, and an unknown destination select the expected mock dataset.
- Activity results exclude activities above the current age suitability threshold unless they are family-fun activities.
- Hotel results contain only family-friendly hotels, and short stays contain only hotels rated four stars or higher.
- The result includes at least one cultural experience and one water activity when the available tool data supports them.
- A model-usage span contains the available token attributes.
- Observability is shut down after both successful and failed runs.
- The repository's existing usage test passes, and a TypeScript check completes without errors.

## 8. Implementation boundaries and follow-ups

The following are explicitly out of scope for this MVP: live provider integrations, departure origin and travel dates as user inputs, booking links, persistence, authentication, a web UI, currency conversion, itinerary day scheduling, and numeric budget enforcement.

Before production use, add explicit dates and origin to the travel request, replace string prices with a money type, calculate totals from structured values, verify recommendations against live sources, and add privacy controls before enabling content tracing for real traveler data.
